# Pleos 전용 에뮬레이터 실행 확인

2026-11-15, 공식 Pleos 2.1.0 / Android API 34 시스템 이미지에서 제출용 서명 APK를 실행했습니다. 전체 시스템 화면은 2560×1440이며 앱은 차량 홈의 앱 영역에 표시됩니다. 일반 Android API 35 DEMO 녹화와 별도의 실행입니다.

**이 시험의 위치값은 VirtualConsole이 제공한 에뮬레이터 신호입니다.** 앱 내부의 DEMO fixture가 아닌 Pleos Vehicle SDK 실제 콜백·현재값 조회 경로를 확인했으며, 실차·물리 창문·순정 스위치가 작동한 시험은 아닙니다. 사용 빈도, 비용 절감, 수리 효과는 이 시험으로 검증하지 않았습니다.

## 절차와 결과

1. 공식 이미지 cold boot 후 제출 APK를 설치하고 실행했습니다. APK SHA-256은 프로젝트 README의 `b4baaed3…6e46`과 같은 파일입니다.
2. 앱에서 Pleos 차량 읽기 모드를 선택하고 요청된 정상 권한을 허용했습니다. VirtualConsole의 DDS ONLINE 연결을 확인하고 창 위치를 바꿨습니다. 앱이 Vehicle 2.3.2 읽기 연결과 P·정지 확인을 표시했습니다.
3. 에뮬레이터의 닫힘 상태를 기준으로 앱의 닫힘 확인 절차를 진행했습니다. 동일한 사용자 조건인 ‘주차 후 첫 조작’을 선택했습니다.
4. 앱의 관찰 시작 후 VirtualConsole의 운전석 창 위치를 아래 순서로 변경하고, 앱에서 관찰 종료와 저장을 눌렀습니다. 각 종료 조회값도 기록에 포함되었습니다.

| 단계 | 시작·변경·종료 조회 순서 | 수신점 | 표시 결과 |
|---|---|---:|---|
| 정비 전 | 80 → 60 → 30 → 10 → 25 → 40 → 종료 조회 40 | 7개 | 다시 내려옴 |
| 인수할 때 | 80 → 60 → 30 → 0 → 종료 조회 0 | 5개 | 이번에는 닫힘 |
| 일상 재확인 | 80 → 60 → 30 → 10 → 25 → 40 → 종료 조회 40 | 7개 | 다시 내려옴 |

5. 세 기록의 비교 화면에서 수신점 수, 동일 조건 표시와 되돌아옴/닫힘/재발 패턴을 확인했습니다. 이는 설정한 신호에 대한 앱 처리 결과입니다. 정비 성공이나 고장의 재발을 실증한 것이 아닙니다.
6. 별도 관찰을 시작한 뒤 에뮬레이터의 기어를 D로 변경했습니다. Pleos 플랫폼이 ‘주행 중에는 사용할 수 없습니다’ 화면을 표시했습니다. P로 돌린 뒤 앱이 해당 시도를 ‘관찰 불충분’, 1개 관찰점으로 처리한 것을 확인했습니다. 이 시도는 저장하지 않고 취소했습니다.
7. 앱을 강제종료한 뒤 fixture 인자 없이 일반 실행했습니다. 기본 DEMO 모드에 0개가 표시된 것을 확인하고 배너에서 ‘Pleos 차량 데이터 읽기’를 다시 선택했습니다. 저장된 3개 기록과 각 7/5/7개 수신점, 비교 결과가 그대로 복원됐습니다. 시작 모드 선택의 유지와 기록의 보존은 구분됩니다.

이 실행 검수는 사람이 화면과 신호를 조작해 확인한 결과입니다. 소스에 포함된 단위 테스트 3건과 Android 저장 테스트 1건의 자동 실행 결과와 별도로 기록했습니다.
